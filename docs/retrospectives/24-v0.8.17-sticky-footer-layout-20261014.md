## 数据快照与实现边界

- 用户在本地验收中指出，空态下页脚卡在主内容中部，与上方两层内容形成三层堆叠；同时要求打赏入口单独居中，合法持有提示与备案号放在第二行。
- 根容器改为 `flex min-h-screen flex-col`，主内容区域使用 `flex-1`，页脚使用 `mt-auto`。这是普通文档流吸底：空态时页脚贴底，列表变长时仍由内容自然推下，不会像 `position: fixed` 那样遮挡文件列表。
- 页脚分为两行：第一行只放打赏入口并精确居中；第二行在宽屏显示合法持有提示、分隔符和备案号，在窄屏自然堆叠。
- 备案链接保留 `https://beian.miit.gov.cn/`、新标签页及 `noopener noreferrer`，去掉下划线和额外字重，通过 `font-normal text-inherit no-underline` 继承第二行文案的系统字体、11px 字号、400 字重与低对比度颜色。
- 本版没有新按钮、新异步流程或新事件名，因此不新增埋点、后台映射或 API 字段。

## 本次故障与根因

1. 本地 Git 分支仍落后远端 `main`，且 GitHub HTTPS fetch 路径不稳定。发布分支使用 GitHub Git Data API 从远端 `main` 创建，第一次创建请求遇到短暂 502，确认远端未产生半成品后重试成功。合并前再次确认 ahead 1、behind 0，仅包含 6 个目标文件。
2. 公开配置复验时，阿里云服务器未安装 `jq`；改为在本机用 Node.js 只读解析公开 JSON，不安装额外依赖，不修改服务器。
3. Cloudflare Wrangler 本次直连成功，未再使用 v0.8.16 时的临时 SSH 转发。这说明上次更像是路由的间歇故障，但本地 GitHub fetch 仍不稳定，不能视为网络问题已根治。
