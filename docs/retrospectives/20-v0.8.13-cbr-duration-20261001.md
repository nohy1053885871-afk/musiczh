# 复盘 #20 — v0.8.13 CBR 转码时长修复（2026-10-01）

> 当前状态：主站 v0.8.13 已从同一 Git tree 发布到 Cloudflare 与阿里云；运营后台保持 v0.4.24，API 保持 v0.4.17。本次没有修改后台、API、nginx 或旧域跳转开关。

## 数据快照与实现边界

- 根因不是 PCM 被拉长，而是 `wasm-media-encoders` 的流式 LAME 输出关闭了 Xing/VBR 时长头。部分播放器会用首个 MP3 帧的瞬时码率估算整段 VBR 音频；安静片头首帧码率很低时，约 4 分钟内容可被显示成十几分钟。
- 修复把 FLAC/OGG/M4A 共用的 MP3 sink 从 VBR -V 2 改为目标 192 kbps CBR。44.1/48kHz 常规输入输出 192 kbps；低采样率输入由 LAME 限制到 MPEG 允许的固定码率，仍保持 CBR。
- `encoder` 埋点改为 `wasm-lame-cbr-192`，历史 `wasm-lame-v2` 保留为历史枚举；未增加事件名、API 字段或数据库迁移。
- 用户提示改为“最高 192 kbps CBR，兼容性优先”。本次没有改页面布局、颜色、动效或交互结构。

## 本次故障与根因

1. `github.com:443` 的 Git smart HTTP 两次超时，但 `api.github.com` 正常。最终通过 GitHub Git Database API 创建与本地文件树完全一致的远端分支；远端 PR 文件树与本地均为 `f593766d7446`，没有把连接失败误报成代码失败。
2. 首次 Cloudflare 发布在读取 Worker 服务时 `fetch failed`。本机 DNS 将 `api.cloudflare.com` 解析到 `redirect-cnzz` 的自签名证书地址，而 Cloudflare DNS 与 Google DNS 返回一致的官方地址。发布没有关闭 TLS 校验，也没有改系统 DNS，只对单次 Wrangler 进程覆写该域名解析并验证官方证书后重试成功。
3. 通用静态 smoke 把 Cloudflare SPA fallback 返回的 HTML 当作 `.deploy-manifest.json` 解析，因而报 JSON 错误。主域没有公开部署清单是已知架构债务，本次改用 HTML、同源资源和 bundle 内容核验；不能把脚本失败伪装成部署失败或反过来忽略。
4. 生产浏览器文件选择后的状态读取长时间无响应，不能判断是浏览器控制连接、文件注入还是页面处理卡住。自动化单测、本地真实样本与生产 bundle 证据成立，但线上真实上传/下载仍缺一条完整浏览器证据。
