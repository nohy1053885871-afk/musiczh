## 数据快照与实现边界

- QQ 使用说明与支持矩阵的两个下载入口复用同一个运行时配置和统一跳转函数，不把真实网盘地址写入源码、文档、前端环境变量或埋点。
- 运营后台在共享 SQLite 中按正式域名保存两个独立配置键；公开 `/api/config` 只返回当前受信 Host 的安全 HTTPS 地址，不泄露另一域名的值。
- 外部链接优先于构建期回退。`sleepno.cn` 空配置时继续使用既有 `/downloads/qq-music-v19.51-windows.zip`；Cloudflare 空配置、非法值、未知 Host 或接口失败时不跳转并显示不可用提示。
- `qq_download_click` 继续使用既有事件名。只有自托管 ZIP 携带 `sha256`；外部跳转只记录入口 `trigger`，链接本身不进入分析数据。
- 本次只改变下载引导的目标地址，不代理网盘文件、不复制安装包、不改变 QQ 文件解密能力，也不删除可回滚的服务器资产。

## 本次故障与根因

1. 生产后台登录态是 host-only，自动化首次打开配置页时没有可复用会话；项目主登录并手动保存后，公开配置立即给出权威运行态信号。
2. 生产浏览器控制在首页导航和 DOM 读取阶段连续中断。它不影响已经发布的页面，但意味着不能宣称两个线上按钮完成真实点击。
3. 常规 `git push` 在当前网络连接 GitHub 时超时；四个轻量标签改由同一 GitHub 认证的 refs API 创建，并逐项返回目标提交。
