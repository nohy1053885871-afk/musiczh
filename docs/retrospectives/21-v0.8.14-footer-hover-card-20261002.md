## 数据快照与实现边界

- 页脚新增可配置入口。桌面端支持悬浮、键盘聚焦和点击展开；触屏端点击后使用底部弹层。关闭配置或配置不完整时组件不挂载。
- 入口文案最多 10 个 Unicode 字符；图片支持 PNG、JPEG、WebP，单图上限 20 MiB，不限制宽高。前台按固定宽度、原比例自动计算高度，不裁剪图片。
- JPEG 校验允许合法 EOI 后存在尾随数据，以兼容 Motion Photo；仍以真实图片头和尺寸为准，不信任文件扩展名或声明 MIME。
- 新增 `footer_hover_entry_view`、`footer_hover_entry_click`、`footer_hover_card_view`。浮层曝光按每次由关闭变为展开计 PV，后台按 `visitor_id` 去重显示 UV。
- 运营后台配置页支持上传、预览、替换、取消替换和启停；首页新增“打赏浮层曝光”PV/UV 卡片。图片与文案不进入埋点属性。

## 本次故障与根因

1. 首次后台保存失败来自请求解析与图片兼容边界；实现补齐严格 multipart 校验、20 MiB 上限、Motion Photo JPEG 尾随数据兼容，并以自动化测试覆盖保存和读取闭环。
2. 生产数据库约 7.3 GiB，备份脚本要求“数据库两倍大小 + 2 GiB”空闲空间，但服务器仅余约 12.5 GB，导致每日备份自 9 月 3 日后持续失败。清理六份更旧恢复点后空闲增至约 18.3 GB，新备份耗时约 14.4 分钟并完成全套校验。
3. Git smart HTTP 仍连接超时，而 GitHub API 可用。发布分支通过 Git Database API 创建，并以 Git tree SHA `581434b133ae` 对齐本地树；PR、CI、合并和标签均有远端证据。
4. 生产浏览器控制连续超时。静态和接口证据足以确认版本与默认关闭状态，但不足以证明真实浏览器交互，因此明确保留证据边界。
