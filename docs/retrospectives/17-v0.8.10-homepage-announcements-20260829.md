## 数据快照与实现边界

- 公告正文只有一个文本层级，不拆主副标题；行动点为可选项，文案与链接必须同时配置。
- `sleepno.cn` 与 `shiyinmp3.com` 共用 API、账号和 SQLite，但使用两个独立配置键；公开接口只返回当前 Host 的已启用公告。
- 关闭状态按 `siteHost + updatedAt` 保存在当前浏览器；同一版本关闭后不重显，运营再次保存产生新版本后恢复显示。
- 未启用、未知 Host、配置非法或接口失败时公告为 `null`，不阻断上传、解密、转码与下载。
- 生产最终两个开关均为关闭；本次不做定时发布、多公告、富文本、图片、轮播或跨域共享关闭状态。

## 本次故障与根因

1. 密钥值曾进入工具输出，因此不能只清理日志或假设访问范围有限；项目主批准立即轮换 Tunnel Token 与源站 Token。
2. 新 Tunnel Token 经独立 cloudflared 探针确认可连接，但部署 workflow 仍失败。根因不是 Token，而是 `systemctl enable --now` 对已运行服务只保证启用/运行，不保证重启；旧进程继续使用旧 Token。
3. 生产直接执行显式 restart 后立即恢复。代码已改为先 `enable`、再 `restart`，Token 更新与进程生效由同一步保证。
4. 为关闭两个公告开关发起的临时在线备份面对 5.4GB 数据库持续高负载，并与一次 `sleepno.cn` config 500 同时出现。终止备份、删除不完整副本后接口恢复；两行配置变更本身已原子完成，正式每日备份未受影响。
