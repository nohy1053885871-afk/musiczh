## 本次决策

1. XM 是独立解密分支，`.xm` 固定进入 XM parser；NCM/KGM/QMC 算法零改。
2. 输出格式只信真实字节，不信标签或文件名；未知产物不放入下载和转码。
3. 不新增 M4A 气泡。原组件、关闭状态和历史事件名原地扩为
   FLAC/OGG/M4A，统一判断只来自 `MP3_TRANSCODABLE_FORMATS`。
4. XM 解密得到的 M4A 默认保持原格式，用户点击后才转；原始 `.m4a`
   上传与 FLAC/OGG 一样自动转 MP3。两者只在实际进入 M4A 转码时加载
   Mediabunny，WebCodecs 失败再加载裁剪 LibAV.js fallback。
5. XM 样本没有内嵌 APIC，解密后的 M4A 也没有 covr，但外层 COMM 带
   喜马拉雅 CDN 封面地址。兼容其非标准 UTF-16 布局后抓图；M4A 在
   进入可下载状态前重封装写入 covr，AAC encoded packets 原样复制，
   后续转 MP3 时同一封面再写入 ID3 APIC。
6. MP3 的 APIC 解码兼容性比 M4A covr 更挑图片编码。统一写标签函数在
   APIC 写入前检查封面：兼容的 JFIF Baseline JPEG 不重编码；Progressive、
   Adobe、非 JFIF 或其他可解码图片转成 sRGB JFIF Baseline JPEG。音频
   字节不参与这一处理，NCM、XM 和全部转 MP3 路径共享同一实现。
7. 发布只涉及主站和运营后台；不执行 server 部署，也不使用会触发三端
   部署的 `v*` tag。
