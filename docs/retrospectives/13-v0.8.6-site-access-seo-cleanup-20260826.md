## 数据快照与问题边界

- 域名风险要求公开入口能立即收紧到指定 IP，同时保留不受限制的后台恢复路径。
- 单表唯一地址约束消除了白名单和黑名单同时命中的冲突；规则顺序固定为黑名单拒绝、白名单模式判断、放行。
- 当前后台请求 IP 自动加入白名单；直接删除被拒绝，移入黑名单必须强确认，恢复访问使用同一行原子切换。
- 本次只清除 HTML、robots、sitemap 和 OG 资产中的 SEO 宣传层。首页平台能力文案、QQ 引导、下载路径、错误提示、埋点、README 和研发文档均未删除。
- 访问控制落在 nginx `auth_request`，所以已完整加载到浏览器内的旧页面只能在刷新或再次请求资源时被拦截。

## 实现与本地验收

- API 新增 `site_access_restricted` 和 `site_access_ip_rules`，精确解析并规范化 IPv4/IPv6，拒绝 CIDR、主机名、端口、zone identifier 与回环规则配置。
- 内部判定只读取 nginx 覆盖的 `X-Real-IP`；黑名单始终拒绝，存储异常显式返回 500，回环地址仅供服务器内部验收隐式放行。
- 后台配置中心增加独立访问控制卡片，覆盖双列表、备注、原子移动、当前 IP 强确认、恢复访问、失败保留服务端状态与重试。
- nginx 模板豁免 `/admin/`、`/api/admin/`、`/api/health`，统一限制主站、静态资源、下载和公开 API，并为页面/API 分别返回中性 HTML/JSON 403。
- 部署流水线改为先按 `.deploy-manifest.json` 校验服务器目录全部文件，再用服务器回环验 nginx；公网 smoke 根据内部判定接受 200 或预期 403，回滚复用相同逻辑。
- `index.html` 只保留通用标题与 `noindex, nofollow, noarchive`，robots 全站禁止；sitemap 和两份 OG 图片资产已删除。
