> 当前状态：本地实现、三端验收与生产发布全部完成。

## 数据快照与根因

- 失败日志 #65207 来自 macOS Safari 14.1，NCM 在 `decrypt` 阶段报
  `UNKNOWN / 处理进程异常退出，请重试`。
- 音频文件大小 11,560,458 bytes，未触及 200 MiB 限制；问题发生在 module Worker
  启动/执行边界，不是 NCM 文件本身或封面回填。
- 当前构建和 Worker 架构正式支持门槛固定为 Chrome/Chromium 111、Edge 111、
  Firefox 114、macOS Safari 16.4、iOS/iPadOS WebKit 16.4。
- 产品决策是不为 Safari 14 增加 classic Worker 双构建，也不牺牲 WASM 动态分包；只对
  “已识别且明确低于门槛”的环境给一次非阻断提示，未知 UA 不猜测。

## 实现与边界

- 新增无依赖兼容判断器：iOS 浏览器统一按系统 WebKit 版本判断；Chromium 优先读取
  User-Agent Client Hints，回退 UA；版本按数字段比较。
- 弹窗标题为“浏览器版本过低”，正文为项目主确认文案；确定、关闭、Esc、遮罩均可结束
  提示，不禁用上传或改变解密/转码流程。
- 正式环境同一标签页会话最多提示一次；关闭后写 `sessionStorage`，不可用时退回模块内存。
  本地 `?preview=browser-compat` 只用于强制检查视觉，不代表真实兼容判断。
- 判断在首屏 React commit 后执行；弹窗用 `React.lazy` 独立分包，支持浏览器不请求弹窗 JS。
- 埋点增加 view / confirm / close 和浏览器版本字段；API 只扩白名单和按版本聚合，不改表；
  运营后台在既有按钮埋点页增加专用统计表，不增加一级导航。
