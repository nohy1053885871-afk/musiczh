# v0.8.6 IP 访问控制与 SEO 宣传清理实施计划

> 状态：2026-08-26 已完成本地实现与验收；尚未提交、合并或上线。生产 nginx 验证与访问矩阵等待项目主明确发布授权。

## 一、目标与边界

1. 公开主站、静态资源、下载目录和公开 API 统一经过 nginx `auth_request`；运营后台、管理 API 和健康检查保持可达。
2. 黑名单始终拒绝；白名单限制模式开启后，未进入白名单的地址也拒绝。判定顺序固定为：黑名单 → 白名单模式 → 放行。
3. 每个规范化 IPv4/IPv6 只有一条 `allow` 或 `deny` 规则，可附备注并原子切换列表；不支持 CIDR、主机名或带端口地址。
4. 当前后台请求 IP 自动加入白名单且不能直接删除；经强确认可移入黑名单，之后仍可从后台恢复到白名单。
5. 只删除生产主站 SEO 宣传层；首页平台文案、格式总览、QQ 引导、安装包、错误提示、解密能力、README 和研发文档保持不变。
6. 本地实现与验证完成后停止；未获项目主明确“上线”授权前，不提交、合并、部署或修改生产 nginx。

## 二、实现

1. API 与 SQLite
   - `feature_flags.site_access_restricted` 保存白名单模式，缺失或非法值默认关闭。
   - 新增 `site_access_ip_rules`，地址唯一，规则限定为 `allow | deny`。
   - 新增管理员状态、自动加入当前 IP、新增、修改/移动、删除和模式切换接口。
   - 新增 nginx 内部检查接口；仅信任 `X-Real-IP`，允许返回 204，拒绝返回 403，存储异常返回 500。
2. 运营后台
   - 保留首页指引开关，新增独立访问控制卡片。
   - 展示当前 IP、限制状态、白名单/黑名单、备注和时间；覆盖新增、编辑、移动、删除、强确认、失败回退和重试。
3. 主站与 SEO
   - 标题收敛为“拾音”，移除 canonical、description、keywords、OG/Twitter、JSON-LD 和 SEO noscript。
   - 增加 `noindex, nofollow, noarchive`；robots 全站禁止；删除 sitemap 与 OG 图片。
   - 新增无脚本、无外部资源的极简 403 页面。
4. nginx、CI 与运维
   - 提供可复制的 nginx 配置模板和部署说明，公开网页返回 403 HTML，公开 API 返回 403 JSON。
   - 用户端 CI 改为服务器目录全量哈希校验 + 回环 nginx smoke，兼容公网 Runner 在限制模式下得到 403。
   - 后台 smoke 和 `/api/health` 继续要求 200，回滚走相同限制感知校验。
5. 版本
   - 主站 v0.8.6、运营后台 v0.4.19、API v0.4.11。

## 三、验证

1. 自动测试覆盖 IP 规范化、默认值、持久化、鉴权、非法输入、重复地址、原子移动、当前 IP 保护、黑名单常开和白名单模式矩阵。
2. 原首页指引公开配置与管理员开关测试继续通过；运行主站、后台和 API 三端构建。
3. 构建产物不得包含 SEO 宣传节点或已删除资产，同时必须保留首页平台功能文案、安装包入口和错误提示。
4. 本地浏览器在 1280×720 与 390×667 验证配置中心布局和全部交互；API 重启后状态必须保持。
5. 生产阶段另行验证开放普通 IP=200、开放黑名单=403、限制白名单=200、限制其他/黑名单=403；后台与健康检查始终 200。

## 四、上线顺序与观测

1. 合并后自动部署主站/后台，再手动 dispatch API。
2. 备份生产 nginx，应用模板，`nginx -t` 成功后 reload。
3. 配置中心确认当前 IP 已进入白名单，配置黑名单，再开启白名单限制。
4. 用当前网络与独立外网完成正反向验收，最后创建三端版本标签并写复盘。
5. 上线后 1 小时和 24 小时观察 nginx 200/403、内部鉴权 5xx、pm2 日志、后台恢复路径和限制模式下的部署流水线。

已完整加载到浏览器的旧纯前端页面无法由服务器收回；本版只限制后续 HTTP 请求，刷新或再次请求资源后才会收到 403。
