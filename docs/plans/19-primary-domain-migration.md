# 主域迁移与旧域生命周期计划

> 状态：第一阶段进行中。2026-08-31 已确认长期以 `shiyinmp3.com` 为目标主域；
> 过渡期继续让 `shiyinmp3.com` 与 `sleepno.cn` 完整提供服务。后续阶段不按日期自动推进，
> 每次切换都必须由项目主根据真实业务数据明确确认。

## 一、已经确认的业务决策

1. `shiyinmp3.com` 是目标主域和默认品牌入口。
2. `sleepno.cn` 是迁移中的旧域；过渡期仍是完整可用入口，也保留阿里云链路的故障恢复价值。
3. 当前不强制跳转、不停止旧域发布、不删除旧域 API、后台、静态资源、访问控制或 QQ 安装包回退。
4. 两个域名继续共用唯一 Hono API、管理员账号和 SQLite；不建立第二套后端或数据同步层。
5. 后续迁移、重定向和退役均以真实流量、业务能力迁移结果和项目主确认作为门禁，不凭日期或主观判断自动执行。
6. “旧域退役”不等于放弃域名所有权。最终仍应继续持有 `sleepno.cn`，用于永久重定向、防止旧链接劫持和钓鱼风险。

## 二、阶段与当前状态

| 阶段 | `shiyinmp3.com` | `sleepno.cn` | 当前状态 |
|---|---|---|---|
| 1. 双域完整服务 | 目标主域、完整功能 | 旧域、完整功能 | **当前阶段** |
| 2. 主动迁移 | 默认品牌与分享入口 | 保持功能，强化迁移提示 | 等待业务数据与项目主确认 |
| 3. 临时切换 | 承接主要流量 | 页面临时跳转，API/资源继续兼容 | 未开始 |
| 4. 永久切换 | 唯一公开产品入口 | 页面永久 301，保留兼容窗口 | 未开始 |
| 5. 运行能力退役 | 主站、后台与 API 正常 | 仅保留域名和最小重定向 | 未开始 |

任何阶段只能向前推进一档；若新域稳定性、迁移漏斗或用户反馈出现异常，优先回到上一档，
不得跨阶段删除回滚资产。

## 三、阶段 1：双域完整服务

### 当前必须保持

- [x] 两个域名继续从同一提交发布相同主站、后台和 API 语义版本。
- [x] `shiyinmp3.com` 作为文档、分享和日常运营的默认入口。
- [x] `sleepno.cn` 保持完整主站、同源 API、应急后台、访问控制和 QQ 自托管回退。
- [x] 首页公告与 QQ 下载链接继续按域名独立配置。
- [x] 后台 Cookie、`visitor_id` 和 `session_id` 继续按 Origin 隔离。
- [ ] 建立迁移观察指标，能够分别看到旧域使用、新域承接和迁移入口转化。
- [ ] 收口双域生产发布编排，确保阿里云、API 与 Cloudflare 均锁定同一提交。
- [ ] 给 Cloudflare 增加可读取且不会被 SPA fallback 吞掉的部署清单。

### 本阶段发布完成定义

1. `shiyinmp3.com` 是主验收入口，首页、后台、API 和真实转换必须通过。
2. `sleepno.cn` 是兼容验收入口；在进入重定向阶段前，仍必须通过同等级功能 smoke。
3. 两边版本与提交一致，只有架构文档登记的运行时配置和接入层差异可以不同。
4. 任一边未部署或验收失败，发布状态只能是“未完成”或“临时不一致”。

## 四、阶段 2：主动迁移

只有项目主根据阶段 1 数据明确确认后才执行：

- [ ] 老域公告明确 `shiyinmp3.com` 为新主域，并提供可观测的迁移行动点。
- [ ] 所有新生成的文档、分享链接、运营物料和后台说明默认使用 `shiyinmp3.com`。
- [ ] 增加受控迁移来源字段，例如 `migration_source=sleepno`；不得跨域复制 `visitor_id`。
- [ ] 后台增加迁移观察区：旧域 PV/UV、迁移公告曝光/点击、新域迁移落地、两域核心漏斗和失败率。
- [ ] 给 `sleepno.cn` 配置经过验证的 QQ 外部下载链接。
- [ ] 观察稳定后再移除旧域自托管 ZIP、SHA-256 运维记录和 nginx `/downloads/` 例外。
- [ ] 将 `shiyinmp3.com/admin/` 固定为日常后台；`sleepno.cn/admin/` 只作为应急入口。
- [ ] 收紧 `preview` 与 `workers.dev` 的生产后台暴露，不把它们当作隔离测试环境。

### 进入阶段 3 前必须确认

- 新域核心转换、下载和后台操作持续稳定；
- 新域 API/Tunnel 没有不可接受的 5xx、超时或性能退化；
- 所有公开链接和运营入口已经默认指向新域；
- 老域不存在尚未迁移的独有能力；
- QQ 下载不再依赖老域自托管资产；
- 老域真实使用量和迁移转化已有足够观察窗口；
- 临时跳转、回滚和缓存兼容方案已经演练；
- 项目主明确批准开始临时跳转。

不预先写死流量比例、天数或转化阈值；届时使用真实基线制定门槛，并在阶段切换记录中固化。

## 五、阶段 3：临时切换

- [ ] 由项目主在运营后台明确开启 `legacy_domain_redirect_enabled`；该开关代码默认关闭，
      发布能力本身不代表批准进入本阶段。
- [ ] 只对老域普通页面的 GET/HEAD 导航启用临时跳转，并保留路径和查询参数。
- [ ] `/api/*` 继续在旧域服务，不把 POST 请求重定向到新域。
- [ ] `/assets/*`、Web Worker、WASM 和其他旧页面依赖资源继续保留缓存兼容期。
- [ ] `/downloads/*` 仅在 QQ 链路完成迁移后移除。
- [ ] `/admin/*` 初期保留应急访问；若改为跳转，明确新域需要重新登录。
- [ ] `/.well-known/*` 和证书验证路径继续保留。
- [ ] 观察迁移落地、旧页面资源 404、旧域 API 请求量和用户反馈。
- [ ] 出现异常时撤销临时跳转，恢复阶段 2 的完整旧域页面。

## 六、阶段 4：永久切换

只有临时切换稳定且项目主再次确认后才执行：

- [ ] 老域普通页面改为永久 301，保留路径和查询参数且无循环。
- [ ] 老域后台跳转到 `shiyinmp3.com/admin/`，明确 host-only Cookie 不迁移。
- [ ] 旧域 API 和静态资源继续保留约定的兼容窗口。
- [ ] 发布验收从“旧域功能一致”改为“301、兼容资源和旧 API 行为正确”。
- [ ] 保留一键恢复旧域静态页面的回滚能力，直到兼容窗口结束。

## 七、阶段 5：旧域运行能力退役

- [ ] 停止向阿里云旧域发布用户端和后台静态产物。
- [ ] 下线 `sleepno.cn/admin/` 和旧域 `/api/*` 入口。
- [ ] 删除只服务旧域的 nginx IP 访问控制、受限页和下载目录。
- [ ] 保留 `sleepno.cn` 域名续费、TLS 和最小永久重定向。
- [ ] 保留 `site_host='sleepno.cn'`、历史 PV/UV、配置键、复盘与发布记录，不回填或改写历史。
- [ ] 后台将旧域数据标记为“旧域历史”，而不是删除统计维度。

## 八、重定向路径边界

| 路径 | 阶段 1–2 | 阶段 3 | 阶段 4 | 阶段 5 |
|---|---|---|---|---|
| `/`、普通页面 | 完整服务 | 临时跳转 | 永久 301 | 永久 301 |
| `/admin/*` | 应急后台 | 默认保留 | 跳转到新域后台 | 不再提供旧后台 |
| `/api/*` | 正常服务 | 继续服务 | 兼容窗口内继续服务 | 关闭旧入口 |
| `/assets/*`、Worker、WASM | 正常服务 | 保留 | 兼容窗口内保留 | 关闭或最小保留 |
| `/downloads/*` | 自托管回退 | 迁移完成后移除 | 不再依赖 | 删除 |
| `/.well-known/*` | 保留 | 保留 | 保留 | 按最终证书方案处理 |

## 九、迁移观测口径

| 验证什么 | 事件 / 信号 | 解释边界 |
|---|---|---|
| 旧域仍有多少使用 | `sleepno.cn` PV/UV、上传、转换、下载 | 跨域 UV 不能自然人去重 |
| 迁移提示是否被看到 | 老域 `homepage_announcement_view` | 按 `site_host` 拆分 |
| 用户是否主动迁移 | 老域 `homepage_announcement_action_click` | 点击不等于新域完成使用 |
| 新域是否承接成功 | 新域迁移落地 pageview、上传/转换/下载漏斗 | 使用白名单迁移来源，不复制访客 ID |
| 新域稳定性 | Worker/Tunnel/API 5xx、超时、核心失败率 | 与发布前基线比较，不预设虚假目标 |
| 旧域是否可退出 | 旧域业务事件、旧 API 请求、旧资源请求 | 必须覆盖缓存旧页面和长尾入口 |

## 十、未来改动资产清单

阶段切换时按下列边界逐项核对，不能只改首页跳转：

| 边界 | 当前依赖 | 未来处理原则 |
|---|---|---|
| 浏览器本地状态 | `src/lib/analytics.ts` 与 `src/App.tsx` 仍使用 `_sleepno_*` 存储键 | 不直接改名导致目标主域访客 ID、会话或关闭状态重置；若要品牌收口，先设计兼容读取、单向迁移与回滚 |
| 站点 Host 识别 | `server/src/lib/siteHost.ts`、`src/lib/public-config.ts` 与后台类型显式列出两个域名 | 阶段 1–4 保持识别；阶段 5 只移除旧域的实时入口资格，仍保留历史查询维度 |
| CORS 与来源信任 | 生产 `ALLOWED_ORIGINS` 同时包含两个域名，Worker/Tunnel 另有专用源站 Host | 旧域 API 真正关闭后再移除 `sleepno.cn`；不能提前让旧页面请求无声失败 |
| 运行时配置 | 公告与 QQ 链接使用 `homepage_announcement_sleepno_cn`、`qq_installer_link_sleepno_cn` 等独立键 | 退役后转为只读历史或归档，不删除到无法解释历史状态 |
| 旧域跳转开关 | `legacy_domain_redirect_enabled` 默认关闭，仅由 `sleepno.cn` nginx 消费 | 阶段 3 才允许开启；永久 301 必须另行批准，不能复用临时开关偷偷升级 |
| 统计与数据库 | `site_host`、`pv_sleepno_cn`、`has_pageview_sleepno_cn` 等字段保存旧域流量 | 永久保留历史口径；后台筛选项最终标为“旧域历史”，不要重命名列或回填数据 |
| 运营后台 | 域名标签、公告/QQ 配置、分域趋势和旧域 IP 控制都显式展示 `sleepno.cn` | 随阶段从“迁移期旧域”改为“跳转中/旧域历史”；不能在入口关闭前先删操作能力 |
| CI/CD 与回滚 | `deploy.yml`、`rollback-frontend.yml` 和 smoke 脚本仍部署、检查 `sleepno.cn` | 阶段 3–4 改验收语义而非直接删除；阶段 5 才停止旧域产物发布，并保留重定向 smoke |
| nginx 与下载资产 | 旧域静态目录、后台 alias、API 反代、IP 规则、受限页和 `/downloads/` | 按路径兼容窗口逐项下线；QQ 外链稳定前不得删除自托管 ZIP 和校验记录 |
| Cloudflare 控制面 | `www` Redirect Rule、DNS、证书、Worker、Tunnel 状态部分不在 git | 每次阶段变更单独导出或记录证据；普通代码发布不能顺手改变 Redirect Rule |
| 监控与版本证据 | 两域 health/smoke、Worker 版本 ID；Cloudflare 尚无可读取部署清单 | 先补部署清单和分链路监控，再降低旧域验收等级 |

## 十一、不可自动执行的事项

以下动作必须由项目主在对应阶段再次明确批准：

- 给老域启用任何强制跳转；
- 将临时跳转改为永久 301；
- 停止旧域前端发布；
- 关闭旧域后台或 API；
- 删除 QQ 自托管安装包、nginx 下载规则或访问控制；
- 从生产 allowlist、Host 识别或 CORS 配置中移除 `sleepno.cn`；
- 放弃或停止续费 `sleepno.cn`。
