# 旧域临时跳转开关实施计划

> 状态：2026-09-17 已从同一提交发布到 Cloudflare 与阿里云，生产开关保持关闭。部署代码不等于
> 批准从主域迁移阶段 1 进入阶段 3；
> 实际开启必须由项目主在完成阶段 2 门禁后再次明确确认。

## 一、目标与边界

- 运营后台提供单一布尔开关，目标固定为 `https://shiyinmp3.com`。
- 开启后，`sleepno.cn` 普通页面 GET/HEAD 返回 307，保留路径和查询参数。
- `/admin/*`、`/api/*`、静态资源、Worker/WASM、`/downloads/*` 与 `/.well-known/*`
  不跳转，继续承担恢复和缓存兼容职责。
- 永久 301、关闭旧域 API/后台、删除静态目录和 QQ 下载回退均不在本期。
- 数据库缺行、非法值或首次升级时一律关闭；目标地址不可运营配置，避免开放重定向。

## 二、改动范围

1. API/schema：开关持久化、管理员读写接口、内部 204/307/403/500 判定协议。
2. 运营后台：独立高风险卡片、加载失败保护、开启二次确认和立即关闭回滚。
3. 旧域 nginx：固定目标 307、路径豁免、迁移来源参数和既有 IP 控制共存。
4. 主站埋点：目标主域记录一次 `migration_source=sleepno` 后清理地址栏参数。
5. CI/运维：部署与回滚 smoke 同时验证目录、回环旧站和公网条件响应。

## 三、验证矩阵

- [x] 开关默认关闭、非法值关闭、重启持久化。
- [x] 管理接口鉴权、严格 payload 和公开配置不泄漏。
- [x] 普通 GET/HEAD 触发 307；POST 和全部兼容路径不触发。
- [x] 跳转保留路径、原查询参数并追加迁移来源；目标主域清理来源参数。
- [x] 服务器回环继续读取旧域真实 HTML/资源；公网 smoke 能区分 200/403/307。生产 nginx
      已备份、通过 `nginx -t` 并 reload；关闭态旧域普通页面保持 200。
- [x] 后台桌面与窄屏无横向溢出；真实登录、开启确认、保存与关闭回滚通过。
- [x] 主站、后台、API 构建、Cloudflare dry-run 与相关专项测试通过。

## 四、发布与启用顺序

1. 合并代码但保持数据库默认关闭。
2. 先手动部署唯一 API，再备份并更新 `sleepno.cn` nginx，`nginx -t` 成功后 reload。
3. 从同一提交发布阿里云与 Cloudflare 用户端/后台，并在关闭态完成双域 smoke。
4. 项目主另行确认进入阶段 3 后，从目标主域后台开启临时跳转。
5. 验证异常时先关闭开关；API 故障无法操作后台时恢复 API，必要时回滚 nginx 备份。

## 五、上线观测指标

| 验证什么 | 信号 | 期望趋势 | 窗口 |
|---|---|---|---|
| 旧域跳转生效 | `sleepno.cn` nginx 普通页面 307 | 开启后普通页面接近全部为 307，无错误目标 | 当次、1h |
| 策略链路稳定 | 内部判定 500、nginx 5xx、PM2 错误日志 | 500/5xx 为 0，无数据库异常 | 当次、1h、24h |
| 新域成功承接 | `pageview.props.migration_source='sleepno'` | 开启后出现并与旧域 307 同向变化 | 1h、24h、7d |
| 核心能力稳定 | 新域上传、转换、下载漏斗与失败率 | 无相对基线的异常恶化 | 1h、24h、7d |
| 兼容窗口仍有需求 | 旧域 `/api/*`、资源、WASM、下载请求 | 初期允许存在，逐步下降，不提前删除 | 24h、7d |
| 恢复通道可靠 | 两个 `/admin/`、旧域 `/api/health`、一键关闭 | 始终可达，关闭后旧域恢复既有行为 | 当次 |
