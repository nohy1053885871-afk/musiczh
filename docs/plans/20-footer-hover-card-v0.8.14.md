# v0.8.14 页脚悬浮图配置计划

## 目标与边界

- 在主站现有页脚声明上方增加一个可配置文字入口，不替换、不弱化“本地处理”声明。
- 桌面端悬浮、键盘聚焦或点击入口展示图片；触屏端点击后以底部弹层展示。
- 运营后台统一配置入口文案、图片和显示开关；配置同时作用于两个正式域名。
- 图片仅保存在现有 SQLite，不引入对象存储；仅保留当前版本，不保存历史图片。
- 本迭代不变更旧域跳转开关、不发布生产环境。

## 数据与接口

- `feature_flags.footer_hover_card` 保存 `{ enabled, label }`。
- `config_assets.footer_hover_card_image` 保存校验后的图片二进制和 MIME、尺寸、SHA-256、更新时间。
- 后台接口：`GET/PUT /api/admin/footer-hover-card` 与受鉴权保护的图片读取接口。
- 公开接口：`GET /api/config` 返回配置元数据；图片通过同源 `/api/config/footer-hover-card/image` 延迟加载。
- 接受 PNG/JPEG/WebP，最大 20 MiB，不限制图片宽高；前后端均校验体积与类型，后端以真实文件头为准，并兼容 JPEG 动态照片等在主图结束标记后附加数据的常见文件。

## 交互与降级

- 文案最多 10 个字符；开启展示必须同时有合法文案和图片。
- 主站配置请求失败、配置不完整或图片加载失败时只隐藏新增入口，其他功能不受影响。
- 桌面浮层保留 120 ms 移出缓冲，避免鼠标从文字移动到图片时闪退。
- 移动端支持遮罩、关闭按钮与 Esc 关闭；打开时锁定页面滚动。
- 图片在固定宽度容器内按原比例自动增高，不裁切、不设最大显示高度；首次展开前不发起图片请求。
- 每次浮层由关闭变为打开时上报 `footer_hover_card_view`；运营后台首页按所选时间范围展示曝光 PV 与去重 UV。

## 验证范围

- API：鉴权、非法 multipart、真实文件头、JPEG 尾部附加数据、20 MiB 体积上限、旧表约束迁移、原子保存、关闭与删除、公开读取。
- 用户端：旧 API 回退、严格解析、桌面悬浮/聚焦、触屏弹层、图片懒加载、窄屏布局。
- 运营后台：加载失败保护、上传预校验、替换/取消、移除联动关闭、保存反馈，以及首页打赏浮层曝光 PV/UV 卡片。
- 构建：用户端、运营后台、API，以及 Cloudflare 组合构建。

## 上线观测指标

| 窗口 | 验证内容 | 事件 / 信号 | 期望 |
|---|---|---|---|
| 首 1 小时 | 配置与图片接口可用 | API 2xx/4xx/5xx、两域 smoke | 无 5xx，两域配置一致 |
| 24 小时 | 入口可发现且能展开 | `footer_hover_entry_view` → `footer_hover_card_view` | 展开 UV 小于等于入口曝光 UV，触发来源分布合理；PV 允许同一访客重复展开 |
| 24 小时 | 移动端点击链路 | `footer_hover_entry_click`、`trigger='click'` | 点击后有对应展开，无异常断层 |
| 7 天 | 不伤害核心流程 | `upload_attempt`、`decrypt_done`、`download_done` | 与上线前同周期无显著负向偏移 |

生产发布需按双域发布流程执行；只有两个域名的配置、图片、首页和窄屏 smoke 都通过才可宣布完成。
